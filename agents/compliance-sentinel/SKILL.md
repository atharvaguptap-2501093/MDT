DATE LOGIC — cumulative total missing weeks since tracking began, NOT a rolling since-last-check window, and NOT reset just because someone submits again:
- current_run_date = today's real date, unless a human operator explicitly tells you in this conversation to assume a different date — if so, use that, and say so in the summary email.
- tracked_weeks = the full set of distinct WeekEndingDate values present anywhere in Timesheet Extraction that fall on or before current_run_date (this naturally starts at 2026-06-07 and grows as new weeks get added — don't hardcode the list, derive it from the data each run).
- For each tracked employee, submitted_weeks = the set of WeekEndingDate values among THEIR OWN Timesheet Extraction rows. ApprovalStatus is irrelevant here (that's the Approval Steward's concern).
- new_total = count of tracked_weeks NOT in that employee's submitted_weeks — i.e. their TOTAL distinct missing weeks so far, from the very start of tracking through current_run_date. This is a cumulative count: it does not reset when someone submits a week on time, it only grows when a new gap appears.
- prev_total = that employee's current Defaulter List column F value (0 if this is their first time on the list).
- Compare new_total to prev_total:
  - new_total > prev_total → a NEW gap appeared since the last check. This is the only case that produces an email. tier = new_total (1, 2, or 3+). Update the row: F=new_total, G="On Track" if new_total==0 (won't happen in this branch, but harmless), else "Defaulter" (new_total 1-2) or "Escalated" (new_total>=3); H=current_run_date; I=current_run_date; J=the tier label.
  - new_total == prev_total → NOTHING changed since last time (they either have zero misses and still do, or they have some old unresolved gap(s) but didn't add a new one this week). Do NOT send an email and do NOT modify this row at all — leave column F/G/H/I/J exactly as they are. This is the "nothing to do about old reminders" case: if the gap never gets backfilled, no further action is taken on it unless a NEW gap appears later; if it does get backfilled (rare), the next run's new_total will simply come out lower — see below.
  - new_total < prev_total → the employee backfilled one or more old missing weeks. Update F=new_total, G recalculated the same way as above (including "On Track" if it's now 0), H=current_run_date, but do NOT send a "reminder" email for this — it's an improvement, not a new miss. (You may still include it in the summary email's tally as a data point, but no per-person email.)
